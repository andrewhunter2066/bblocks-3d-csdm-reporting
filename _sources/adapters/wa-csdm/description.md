# WA 3D CSDM reporting adapter

This block interprets cadastral survey datasets (CSDs) that follow the [WA profile of the 3D CSDM](https://surroundaustralia.github.io/3d-csdm-profile-wa/) and extracts the source facts that cadastral reports need.
It is the only block in this register that knows CSDM paths and WA vocabularies.
Report semantics (calculations, domain checks) and presentation live in the report blocks, so another source format only needs another adapter.

**Status:** Stage 8 of the implementation plan (`docs/cadastral-reporting-investigation-and-plan.md`).
The block has no schema (decision D3); its examples are CSDM datasets that drive its transforms.

## Transforms

The adapter only interprets the source.
It calculates nothing: derived values come from the report block's `complete` transform, so every source adapter produces the same totals.

Each extracted value is a `ReportValue` whose `sourceRefs` give the [JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901) of the exact source property (e.g. `/parcels/0/features/2/properties/interests/0/entitlementPortion`).
Where the source profile defines that property's IRI, the reference also names it in `property`: today that is only `entitlementPortion`, which the WA profile maps to [LADM](https://ogcincubator.github.io/bblocks-land-parcels/bblock/ogc.ladm.land-parcels.ontology)'s `https://w3id.org/ogc/ladm/parcels/entitlementPortion`.
No IRI is invented for the other source properties.

| Source situation | Status |
|---|---|
| Value present and usable | `reported` (`lexicalValue` keeps the original when it was converted, e.g. `"117"`) |
| No strata-lot interest, or no `entitlementPortion` | `not-supplied` (pointer to where it was looked for) |
| `entitlementPortion` is not a positive whole number | `invalid` (original kept as `lexicalValue`) |
| Two strata-lot interests give different entitlements | `conflicting` (both pointers) |
| A scheme reference that is not a feature of the dataset | `unresolved` (pointer to the reference) |

## Shared scheme resolution (`resolve-scheme`)

Every strata report needs the same interpretation of the source: identify the scheme, resolve its members (D4) with their lot numbers and membership evidence, and run the membership and scheme-number checks.
Stage 8 moved this out of `to-strata-entitlement-facts` into `resolve-scheme` when the Scheme Composition Report needed it too (the duplication trigger recorded in the investigation, section 3).
Checks about particular members carry member ids (`targetMembers`), which each report turns into pointers to its own content.
See `docs/stage-8-generalisation-check.md`.

## Checks recorded by the adapter

| Check | Category | Severity | Fails when |
|---|---|---|---|
| `scheme-identified` | generation | error | (never in a produced report: no single scheme stops generation) |
| `membership-parcel-aggregate` | domain | error | the scheme's [topology](https://ogcincubator.github.io/topo-feature/bblock/ogc.geo.topo.datatypes.topology) is not `ParcelAggregate` or lists no references |
| `membership-references-resolve` | domain | error | a reference is not a strata-lot parcel of the dataset |
| `membership-back-links` | domain | warning | a member lot's `containingPrimaryParcel` is missing or another parcel, or its `schemeRef` names another parcel (a missing `schemeRef` is acceptable) |
| `membership-unreferenced-claimants` | domain | warning | a strata lot links to the scheme but is not in its references (it is reported, not added) |
| `entitlement-source-datatype` | source-conformance | info | an `entitlementPortion` is a number, while [`icsm.profiles.wa.wa-3d`](https://surroundaustralia.github.io/3d-csdm-profile-wa/bblock/icsm.profiles.wa.wa-3d) types it as a string |
| `scheme-number-consistent` | domain | warning | the `schemeNumber` differs (ignoring spaces) from the CSD `name` or the scheme appellation's `surveyNumber` |

Each member lot's `membershipEvidence` lists `references` (authoritative, D4) and, when they point at the scheme, `containingPrimaryParcel` and `schemeRef`.
The declared total is read from the scheme's `wa-interest-type:strata-scheme` interest (`entitlementTotal`, D10).

| Transform | Output | Notes |
|---|---|---|
| `to-strata-entitlement-facts` | Facts-stage Strata Scheme Entitlement Report (JSON), validated against `csdm.reporting.reports.strata-entitlement` | The only CSDM-specific logic |
| `to-strata-entitlement-report` | Complete report (JSON), validated against the same profile | Composition: `to-strata-entitlement-facts`, then the report block's `complete` |
| `to-strata-entitlement-html` | HTML report | Composition: `to-strata-entitlement-report`, then the report block's `to-html` |
| `to-strata-entitlement-csv` | CSV of the lots | Composition: `to-strata-entitlement-report`, then the report block's `to-csv` |
| `to-scheme-composition-facts` | Facts-stage Scheme Composition Report, validated against `csdm.reporting.reports.scheme-composition` | Members with geometry type, representation status and component solids |
| `to-scheme-composition-report` | Complete Scheme Composition Report | Composition: facts, then the report block's `complete` |
| `to-scheme-composition-html` | HTML report | Composition: report, then the report block's `to-html` |
| `resolve-scheme` | The resolved scheme, its members and the membership checks (JSON, not a report) | Shared by both facts transforms through `get_transformer()` (see below) |
| `vocabulary-labels` | WA vocabulary label table (JSON) | Generated; used by the other transforms through `get_transformer()` (see below) |

## Fixture

`examples/sp83687-entitlement.json` is derived from the full SP83687 dataset (`data/examples/json/built-strata-example-1.json`) by `scripts/trim_csdm_fixture.py`.
That script empties the features of the geometry collections (points, edges, rings, faces, shells, occupation features) and keeps parcels, solids, supporting documents, annotations and provenance unchanged.
The result is ~39 KB instead of ~820 KB.

The fixture keeps the `solids` collection (7 KB), which the Scheme Composition Report needs to tell whether a lot's component solids exist.
It is **not** expected to conform to the source profile: the solids still reference the removed shells.
Source conformance is always checked against the full dataset.

Regenerate it after changing the full dataset:

```bash
python3 scripts/trim_csdm_fixture.py data/examples/json/built-strata-example-1.json \
  _sources/adapters/wa-csdm/examples/sp83687-entitlement.json
```

## Source conformance findings (2026-10-01)

Produced by `scripts/check_source_conformance.sh`.
The script validates the full SP83687 dataset against `icsm.profiles.wa.wa-3d` with the [OGC Building Blocks postprocessor](https://github.com/opengeospatial/bblocks-postprocess) (JSON Schema, [JSON-LD](https://www.w3.org/TR/json-ld11/) uplift with the profile context, inherited [SHACL](https://www.w3.org/TR/shacl/) shapes) and lists every JSON Schema error.
Result: **does not conform**.
Under decision D3 this is recorded, not enforced.
The report pipeline must tolerate it.

| # | Layer | Finding | Count | Affects entitlement report? | Note |
|---|---|---|---|---|---|
| 1 | JSON Schema | `entitlementPortion` is an integer; the schema requires a string | 9 | Yes: coerced to integer, `lexicalValue` kept (D7) | Pending proposal: number (common) / integer (WA) |
| 2 | JSON Schema | ~~`spatialRepresentationDefinitions` is `null` on every strata lot~~ | 9 | No | **Fixed 2026-10-01:** the null property was removed from the lots (not needed for the entitlement report; not required by the profile) |
| 3 | JSON Schema | ~~Former-tenure interest (`wa-title:4027-1000`) has no `interestType`~~ | 1 | No | **Fixed 2026-10-01:** `interestType` = `wa-interest-type:ct` (Certificate of Title, approved WA vocabulary) |
| 4 | SHACL | Supporting-document roles (`wa-survey-documentation-type:*`) are not registered types | 8 | Indirectly: the schedule's role is `unitEntitlementSchedule` | Vocabulary supplement not yet registered (D11) |
| 5 | SHACL | Annotation roles (`wa-annotation-role:*`, which expands to `…/wa-annotation/…`) are not registered types | 6 | Indirectly: certification role | Vocabulary supplement not yet registered (D11) |
| 6 | SHACL | Survey-point `purpose` (`wa-surveypoint-purpose:derived-boundary`) and `condition` (`wa-monument-condition:computed`) lack the expected class | 256 + 256 | No | Vocabulary supplements not yet registered |
| 7 | SHACL | "Referenced features must be present" for the component solids of Lot 1 (4) and Lot 2 (5) | 9 | No | Not a data defect: all 9 are in `solids`. Cause: the published `wa-3d` JSON-LD context has no mapping for `solids` (it maps `shells`, `faces` and `points`), so uplift drops the collection and every referenced solid has no triples. To raise with the profile maintainers. See the note below on Lots 3–9 |

**Lots 3–9 solids (finding 7).**
Only Lots 1 and 2 have [`AggregateSolid`](https://ogcincubator.github.io/topo-feature/bblock/ogc.geo.topo.features.topo-aggregate-solid) component solids so far.
The solids for Lots 3–9 have not been created yet, and their `AggregateSolid` reference lists are empty, so they are not counted in finding 7.
They are not required for this building block: the Strata Scheme Entitlement Report does not use geometry.
Once they are created and referenced, they will be reported under finding 7 too, until the profile context maps `solids`.

Items fixed in the dataset before the first run: `interestLink` on every interest (prefixed names), road labels on `apt:road` values, `apt:addressNumberFirst`, and links from annotations to their documents.
After rows 2 and 3 were fixed, the only remaining JSON Schema finding is row 1.

## What the adapter reads for the basis of the schedule

| Report value | Source |
|---|---|
| Scheme name | the scheme parcel's `schemeName` |
| Address parts | `schemeAddress.hasPart`. The road label is the `label` on the `apt:road` value; the locality label comes from `wa-locality`. The formatted address ("281 Belmont Avenue, Cloverdale") is derived here because it interprets these parts |
| Schedule document | `supportingDocuments[role = wa-survey-documentation-type:unitEntitlementSchedule]` |
| Approved form | the schedule's `conformsTo`; label, validity (`dcterms:valid`, whose start is `validFrom`) and source from `wa-approved-form` |
| Legislative basis | the approved form's `skos:scopeNote` in `wa-approved-form` |
| Certification | `annotations[role = wa-annotation-role:licensed-valuer-certification]`: `certifier`, `dateCertified`, `description` (verbatim), and the document its `href` matches |

Only the schedule document (and any other document the certification links to) and the certification annotation are copied into the report; the dataset's other documents and annotations are not.

## Vocabulary label table

The WA vocabularies the report needs (`wa-locality`, `wa-approved-form`) are not yet published at resolvable IRIs.
`scripts/build_vocabulary_labels.py` therefore generates `transforms/vocabulary_labels.py` (transform `vocabulary-labels`, about 90 KB, mostly the 1,715 WA localities) from the local `.ttl` files below.
A value found there is `reported`, with the vocabulary as its source dataset and the concept IRI as its `id`; a code that is not in the table is `unresolved`.
Re-run the script when a vocabulary changes:

```bash
python3 scripts/build_vocabulary_labels.py   # defaults: ../icsm-vocabs and ../3d-csdm-profile-wa
```

Once the vocabularies are published, the adapter can look them up instead of carrying the table.

## Interpretation rules (to be implemented from Stage 1)

- **Scheme:** the one parcel with `parcelPurpose` = `wa-parcel-purpose:strata-scheme`.
  Zero or several schemes is a generation error, unless a `scheme-id` parameter selects one (D5).
- **Members:** the scheme's `topology.references`, where `topology.type` = `ParcelAggregate`.
  These are authoritative for `wa-built-strata` (D4).
  Each lot's `containingPrimaryParcel` and `schemeRef` are consistency checks only.
- **Entitlements:** `interests[interestType = wa-interest-type:strata-lot].entitlementPortion` per lot.
  The declared total is `interests[interestType = wa-interest-type:strata-scheme].entitlementTotal` on the scheme (D10).
